# Project & Deployment Reference

## Project overview

- **Frontend**: Next.js 14 (App Router), TypeScript, Tailwind, shadcn/ui. Static export (`output: 'export'`) for hosting (e.g. GoDaddy cPanel).
- **Backend**: Node/Express API in `aip-backend/` — auth, doctors, practices, approval-requests, membership-plans, etc. Connects to **Cloud SQL (PostgreSQL)**.
- **Auth**: JWT; tokens stored in `localStorage` (`aip_doctor_token`). Backend validates via `authenticateToken` middleware.

**API base URL**: `NEXT_PUBLIC_API_URL` (default `https://aip-backend-112180822704.us-central1.run.app`). Set in `.env.local` for dev or in the build env for production.

## Deployment

### Frontend (static site, e.g. GoDaddy)

1. Set `NEXT_PUBLIC_API_URL` to your backend URL (build time).
2. Build: `npm run build` → produces `out/`.
3. Deploy contents of `out/` to the web root (e.g. `public_html`). Optionally run `./create-deployment.sh` to get `deployment.zip` from `out/`.

No server process; all API calls go from the browser to the backend URL.

### Backend (GCP Cloud Run)

1. **Code**: All backend logic is in `aip-backend/`. The only file that was changed for tiered approval and error details is:
   - `aip-backend/src/routes/approval-requests.ts`

2. **Deploy** (from repo root):
   ```bash
   cd aip-backend
   ./deploy-to-gcp.sh
   ```
   Script will:
   - Prompt for DB password, JWT secret, frontend URL
   - Build image: `gcr.io/aip-backend-112180822704/aip-backend:latest`
   - Deploy to Cloud Run in `us-central1` with Cloud SQL connection and env vars

3. **Manual deploy** (if you prefer):
   ```bash
   cd aip-backend
   gcloud builds submit --tag gcr.io/aip-backend-112180822704/aip-backend:latest --project=aip-backend-112180822704
   gcloud run deploy aip-backend \
     --image gcr.io/aip-backend-112180822704/aip-backend:latest \
     --platform managed --region us-central1 \
     --allow-unauthenticated \
     --add-cloudsql-instances <CONNECTION_NAME> \
     --set-env-vars "DB_SOCKET_PATH=...,DB_NAME=aip_production,DB_USER=postgres,DB_PASSWORD=...,JWT_SECRET=...,FRONTEND_URL=..." \
     --project=aip-backend-112180822704
   ```

4. **DB**: Ensure migrations are applied (e.g. `aip-backend/migrations/001_approval_requests_schema.sql` on your Cloud SQL instance).

## Key flows (current behavior)

- **Join – new practice**: Apply → Plan → Payment → Review → Submit → `new_practice_with_admin_doctor` created. Admin approves → side effects create practice, doctor, membership, user role.
- **Join – existing practice**: Same flow; user picks “Join an existing practice” and a practice from the list. Creates `doctor_join_practice` with `practice_id`. **Tiered approval**: Practice Admin must approve first; then Admin sees it and can approve. Side effects add doctor to existing practice.
- **Doctor dashboard**: Layout loads doctor via `getDoctor(doctorId)`; response is normalized to camelCase (`fullName`, `firstName`, `lastName`, `practiceId`, etc.) so the UI shows name and practice info.
- **Practice info page**: Uses `doctor.practiceId` (or `practice_id` from API) and fetches practice by ID with `getPractice(practiceId)` so newly created practices are shown.

## Files to deploy when you change something

| Change | Deploy |
|--------|--------|
| Backend (approval-requests, auth, etc.) | Redeploy `aip-backend` to Cloud Run (e.g. `./deploy-to-gcp.sh` or manual `gcloud` above). |
| Frontend (Next.js app, `src/`, `next.config.js`) | Rebuild (`npm run build`) and re-upload `out/` (or your deployment package). |
| DB schema | Run migration SQL against Cloud SQL (no code deploy). |
